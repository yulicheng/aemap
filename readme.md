# 项目目标

考虑一种动态地址映射，支持将48位虚地址动态映射到52位新的地址，应用代码中的指针低32位为offset，32到51位为映射索引，52位及以上忽略。应用代码每次ld或st时使用的地址叫VVA，需要将VVA高51到32位转换成真实的VA的高48到32位，VA低32位直接使用VVA低32位。

一种实现方式是每次ld和st前进行一次内联查表，实现上述映射，并合并低32位，将指针VVA转为VA，再使用VA执行ld或st指令。查表后需要判断表项是否有效，若无效需要调用运行时中的映射创建函数并填充表项。由于多线程可以共享相同表项，要注意线程安全。

本项目需要用最优的指令实现上述查表转换操作，并且需要实现一个mock的运行时库，支持映射创建和销毁，并支持设定不同映射创建时延模拟真实分配代价。

实现需要提供两个架构版本：x86-64 与 aarch64（ARMv9 + SVE2），各自使用对应架构上最优的指令（如 x86-64 上的 BMI2、aarch64 上的 SVE2 等）实现查表转换；对上层应用暴露相同的接口与语义，可按构建目标选择架构实现。

最后设计一套统一的测试框架，同时测试 x86-64 与 aarch64 两个版本，测试这种软件转换带来的overhead。两个版本使用相同的测试用例、参数矩阵与指标口径，保证测试结果可直接对比。测试用例需要覆盖重复访问相近VVA从而使得映射表在L1命中，以及随机访问VVA使得映射表cache miss等等场景。
请进一步补充测试用例，覆盖常见的软件访存pattern，包括但不限于STREAM中的几种访问模式。
按照所有0%、25%、50%、75%、100%访问表项无效、10us、100us、1ms、10ms四种映射建立时延分别测试性能。
测试需要包括单线程和多线程。

以上操作的实现方式在design.md中具体描述。测试框架以及对应的测试用例在test.md中详细描述。
